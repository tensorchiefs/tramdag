    Training strategies: driving fit from the API side¶

    fit runs one minibatch Adam loop per node and keeps the final weights. It owns the loop, the per-epoch validation score and the progress output. The caller controls the rest through optimizer= and callbacks=.

    This notebook runs every shipped strategy on one small workload and ends with a runtime scoreboard. The table in docs/fitting.md tells which strategy to pick.

    1. What fit records without any callback¶

    With validation_data=, fit scores the validation NLL of each node once per epoch. flow.history holds one dict of per-node values per epoch, for the keys that the docstring of CausalFlowDAG.history lists. It is a view over the per-node flow.nodes[name].history.

    3. Two phases¶

    A second fit call continues the training with a new optimizer. A second call at a lower rate is thus a coarse-then-fine schedule. The history accumulates over the calls.

    4. EarlyStopping: keep the best weights¶

    A flexible model can reach its best validation score part way through and then drift. EarlyStopping keeps a copy of each node's best epoch and loads it at the end of that node's fit. After the fit, the validation score of each node equals the minimum over its epochs.

    5. EarlyStopping(patience=): stop each node on its own¶

    With patience, a node also stops once its best epoch is that many epochs old, so each node stops at its own epoch. A dict by node name gives each node its own instance; a defaultdict makes one for every node.

    6. Writing your own¶

    docs/fitting.md gives the callback hooks. Plateau builds torch's ReduceLROnPlateau on the optimizer of each node and steps it on node.history["val"].

    In [10]:
    Copied! 
    class Plateau(Callback):
    """One torch ReduceLROnPlateau per node, driven by fit's own score."""

    def __init__(self, factor=0.3, patience=10):
        self.factor, self.patience = factor, patience
        self.scheduler = None

    def on_fit_begin(self, node, optimizer):
        """Build the scheduler here: the node's optimizer exists only now."""
        self.scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
            optimizer, factor=self.factor, patience=self.patience
        )

    def on_epoch_end(self, node, epoch, optimizer):
        """Step the scheduler, and stop once the rate has bottomed out."""
        self.scheduler.step(node.history["val"][-1])
        return optimizer.param_groups[0]["lr"] < 1e-5

    optimizer= takes a factory f(node). This one gives the networks weight decay in their own parameter group. flow.history["lr"] shows both groups of every node.

    def adam_with_net_decay(node):
    """Adam with weight decay on the network parameters only."""
    groups = node.parameter_groups()
    rest = groups["intercept"] + groups["linear"]
    nets = {"params": groups["networks"], "weight_decay": 1e-4}
    groups = [{"params": rest}, nets]
    return torch.optim.Adam(groups, lr=1e-2)

    Each row gives the wall-clock seconds, the node-epochs summed over the nodes, the validation NLL and its gap to the best recipe. A recipe that stops early wins on seconds only if its NLL stays near the best. The seconds apply to this machine only.
